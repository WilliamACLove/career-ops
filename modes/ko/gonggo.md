# 모드: gonggo -- 전체 평가 A-F

후보자가 채용 공고(텍스트 또는 URL)를 붙여넣으면 항상 6개 블록을 제공합니다.

## Step 0 -- Archetype 감지

공고를 6개 archetype 중 하나로 분류합니다(`_shared.md` 참고). 하이브리드 역할이면 가장 가까운 2개를 표시합니다. 이 분류는 다음을 결정합니다.
- 블록 B에서 우선순위를 둘 proof point
- 블록 E에서 summary를 다시 쓰는 방식
- 블록 F에서 준비할 STAR story

## Step 0.5 -- 법률 자격 Hard Gates (pass/fail -- 절대 점수로 뭉개지 않음)

점수를 매기기 전에 후보자의 `config/profile.yml` -> `legal` 블록을 기준으로 공고를 확인합니다. 이는 가중치를 매기는 요소가 아니라 구조적 필터입니다 -- gate 실패는 red flag 차원과 최종 추천에 **명시적으로** 드러나야 하며, CV match 점수가 좋다고 묻히면 안 됩니다.

1. **변호사 자격 / 등록** -- 공고의 소속(로펌/사내/정부/리걸테크)에 따라 strictness가 다릅니다. **국내 로펌: strict** (변호사 자격 + 등록 구분 확인). **외국계 로펌 한국 오피스/국제 자문: 외국법자문사 등록 요건 확인** (한국 변호사 자격이 없다면 외국법자문사법상 등록 없이는 외국법 자문 업무를 할 수 없음). **사내변호사/컴플라이언스: moderate** (변호사 자격이 필수가 아닌 "법무팀" 포지션도 많음, JD에서 실제 요구사항 확인). **정부/공공, 리걸테크: minimal** (변호사시험 합격 여부 정도가 기준인 경우가 많음).
2. **연차 / PQE band** -- 로펌 lateral 공고가 연차 밴드("3~5년차" 등)를 명시하면 `legal.class_year`와 비교합니다. 밴드를 벗어나면 거의 자동 탈락 -> 지원 비추천을 명시합니다 (연차 재조정은 보통 offer 단계에서 ±1년 정도만 협상 여지가 있습니다).
3. **변리사 자격** -- 특허 출원/중간사건 처리 역할은 변호사 자격과 별개로 변리사 자격(변리사시험 관할)을 요구합니다. `legal.patent_bar`가 false인데 JD가 변리사 자격을 명시하면 hard gate입니다. (상표/저작권/IP 소송은 대개 변리사 자격이 필수가 아닙니다.)
4. **Conflict of interest (시니어/파트너급)** -- 클라이언트 conflict check 통과가 전제조건임을 리스크로 기록하되 점수에는 반영하지 않습니다.

Gate 결과는 블록 B 상단에 짧은 pass/fail 표로 정리합니다. Gate 실패는 나머지 항목이 아무리 잘 맞아도 최종 추천을 제한합니다.

- 한 문장 TL;DR

## 블록 B -- CV와의 매치

`cv.md`를 읽습니다. 공고의 각 자격 요건을 CV의 정확한 문장과 매핑한 표를 만듭니다.

**Archetype에 맞게 조정:**
- 로펌 -- 거래 자문 -> 올바른 연차대 딜사이즈, 딜 유형, 드래프팅 주도권, 전문 workstream 관리 우선
- 로펌 -- 소송·분쟁 -> 변론/서면 경험 우선: 심문, 증인신문, 재판/중재 수행, 글쓰기 역량
- 사내변호사 -> 계약 처리 볼륨(상사계약/SaaS/개인정보보호), cross-functional 자문, 규제 폭, 비즈니스 언어로 설명하는 능력 우선
- 컴플라이언스·규제 대응 -> 담당 regime 명시(자금세탁방지, 공정거래 등), 규제기관 대응 경험, 내부조사, 프로그램 오너십 우선
- 정부·공공 -> 법정/심리 volume, 공익 커밋먼트(로스쿨 클리닉, 국선전담 등) 우선
- 리걸테크·리걸엔지니어 -> 정통 실무 경력 + 실제 product/AI 이해, playbook 구축, 워크플로우 자동화 사이드 프로젝트 우선

**Gaps** 섹션을 만들고 각 gap에 대한 mitigation 전략을 제시합니다. 각 gap마다 다음을 판단합니다.
1. hard blocker인가, nice-to-have인가?
2. 후보자가 인접 경험으로 증명할 수 있는가?
3. 이 gap을 커버하는 portfolio project가 있는가?
4. 구체적인 mitigation plan은 무엇인가? (커버레터 문장, 빠른 mini-project 등)

## 블록 C -- 레벨과 전략

1. 공고에서 감지된 **레벨**(로펌은 연차 band, 사내변호사는 Counsel -> Senior Counsel -> AGC -> GC 직급 사다리) vs 해당 archetype에서 후보자의 **자연스러운 레벨** -- 사내변호사는 title이 comp의 레버입니다.
2. **"거짓 없이 senior로 포지셔닝하기" 계획**: archetype에 맞춘 구체적인 표현, 강조할 실제 매터(deal/case), 로펌 트레이닝·재판연구원·규제기관 경력을 장점으로 배치하는 방법
3. **"downlevel될 경우" 계획**: 로펌은 연차 재조정이 offer 단계에서 ±1년 정도 협상 가능(때로 한 연차 낮춰 파트너 승진 트랙 시간을 버는 선택지도 있음). 사내변호사는 금액보다 먼저 title/레벨(Senior Counsel vs Counsel, AGC vs Senior Counsel)을 협상합니다 -- 성과급 target %와 equity band가 title을 따라가기 때문입니다.

## 블록 D -- 보상과 시장 수요

WebSearch를 사용해 고용 형태별로 구분된 소스를 확인합니다.
- **대형로펌(김앤장, 광장, 태평양, 세종, 율촌 등 "대형로펌" 카테고리):** 급여는 대부분 비공개 협상이며 공개된 lockstep scale이 없습니다. 공고에 금액이 없는 것이 표준이며 그 자체로 red flag가 아닙니다. 헤드헌터/서치펌 정보로 시장 수준을 교차 확인합니다.
- **중소형/부티크 로펌:** 대형로펌 대비 낮은 경우가 많고 사무소별 편차가 커서 일반화하기 어렵습니다.
- **사내변호사/컴플라이언스:** 한국사내변호사회(KCCA) 등 사내변호사 커뮤니티 벤치마킹, 원티드/잡코리아/사람인 공개 공고, 헤드헌터 정보를 참고합니다.
- **정부/공공:** 인사혁신처 공무원 보수 규정 및 소관 기관 보수표(검사 호봉표 등)를 1차 자료로 안내합니다. 정확한 호봉·수당 수치는 매년 바뀌므로 특정 숫자를 지어내지 말고 공식 자료 확인을 권합니다.
- **리걸테크:** 채용 공고에 명시된 range, 원티드 등을 참고합니다.
- 회사의 보상 평판(가능한 경우), 해당 실무 분야의 수요 추세

데이터와 출처를 표로 정리합니다. 데이터가 없으면 명확히 없다고 말합니다. 절대 지어내지 않습니다.

**한국 법률 시장 -- 필수 확인 사항:**
- 세전 연봉 기준인가? 월급/연봉/총보상 기준이 섞여 있지 않은가?
- 성과급, 인센티브, 사이닝 보너스가 별도로 언급되어 있는가? (로펌 bonus는 보통 discretionary)
- 스톡옵션, RSU, 지분 보상이 있는가? (사내변호사/리걸테크에서 흔함) vesting 조건은 명시되어 있는가?
- 정규직인가 계약직인가? 계약직이면 기간, 전환 가능성, 계약 종료 리스크를 확인합니다.
- 수습기간이 있는가? 기간과 급여 차감 여부가 명시되어 있는가?
- 포괄임금제, 고정 OT, 야근/휴일근무 조건이 언급되어 있는가? (송무 실무는 특히 확인 필요)
- 퇴직금, 4대 보험, 연차/휴가, 식대/복지포인트 등 기본 복지가 명시되어 있는가?
- 재택/하이브리드라면 실제 출근 빈도와 지역 제한이 명확한가?
- 연차/PQE band, 변호사 자격/등록 요건, 변리사 자격 필요 여부가 명시되어 있는가? (Step 0.5 hard gates와 교차 확인)

## 블록 F -- 면접 준비 계획

공고의 자격 요건에 매핑한 6-10개 STAR+R story를 준비합니다 (STAR + **Reflection**).

| # | 공고 자격 요건 | STAR+R story | S | T | A | R | Reflection |
|---|----------------|--------------|---|---|---|---|------------|

**Reflection** 열은 무엇을 배웠는지 또는 다시 한다면 무엇을 다르게 할지를 담습니다. 이는 seniority를 보여주는 신호입니다. junior는 무슨 일이 있었는지를 설명하고, senior는 그 경험에서 무엇을 배웠는지까지 설명합니다.

**Story Bank:** `interview-prep/story-bank.md`가 있으면 해당 story들이 이미 있는지 확인합니다. 없으면 새 story를 추가합니다. 시간이 지나면 어떤 면접 질문에도 재사용 가능한 5-10개의 master story bank가 만들어집니다.

**Archetype에 맞춰 선택하고 framing합니다:**
- 로펌 -- 거래 자문 -> 딜 실행, 드래프팅 주도권, 전문 workstream 관리를 강조
- 로펌 -- 소송·분쟁 -> 사건 전략, 승소한 서면/변론, 심문·증인신문 경험을 강조
- 사내변호사 -> 비즈니스 인에이블먼트("안전하게 yes로 만드는 법"), 계약 볼륨 관리, cross-functional 자문을 강조
- 컴플라이언스·규제 대응 -> 프로그램 구축, 규제기관 대응, 처리한 내부조사를 강조
- 정부·공공 -> 법정/심리 volume, 제한된 리소스 안에서의 판단력, 공익 커밋먼트를 강조
- 리걸테크·리걸엔지니어 -> 실무 전문성을 product/워크플로우 의사결정으로 번역한 경험, 도입/채택 지표를 강조

추가로 포함합니다.
- 추천 대표 매터 1개(공개 가능 범위 안에서 어떤 딜/사건을 어떻게 보여줄지 -- confidentiality 유의)
- red-flag 질문과 답변 전략 (예: "왜 로펌을 떠나려 하나요?", "왜 파트너가 되지 못했나요?", "빌러블시간(billable hours) 실적이 어떻게 되나요?", "왜 사내변호사로/다시 로펌으로 가려 하나요?")

### 1. report .md 저장

전체 평가를 `reports/{###}-{company-slug}-{YYYY-MM-DD}.md`에 저장합니다.

- `{###}` = 다음 순차 번호(3자리, zero-padded). 동시성 문제를 피하기 위해 반드시 `node reserve-report-num.mjs`를 실행해 번호를 예약합니다(stdout이 `{###}`를 반환). report를 작성한 뒤 `node reserve-report-num.mjs --release {###}`를 실행해 sentinel을 해제합니다.
- `{company-slug}` = 회사명을 소문자와 하이픈으로 만든 slug
- `{YYYY-MM-DD}` = 오늘 날짜

**Report format:**

```markdown

**Archetype:** {detected}
**Score:** {X/5}
```

### 2. tracker 추가 항목 작성

새 tracker row를 위해 `data/applications.md`를 직접 수정하지 않습니다. 평가마다 `batch/tracker-additions/{num}-{company-slug}.tsv`에 TSV 한 줄을 쓰고, 이후 `node merge-tracker.mjs`로 병합합니다.

**TSV format (status before score):**

```text
{num}\t{date}\t{company}\t{role}\tEvaluated\t{score}/5\t{pdf}\t[{num}](reports/{num}-{company-slug}-{date}.md)\t{note}
```

- `pdf`는 PDF가 생성되면 `✅`, 아니면 `❌`
- report 링크는 root-relative로 작성합니다: `[001](reports/001-company-2026-01-01.md)`
- 이미 같은 company + role이 있으면 새 row를 만들지 말고 기존 entry 업데이트 흐름을 따릅니다.
