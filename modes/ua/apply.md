# Режим: apply — Асистент відгуку в реальному часі

Інтерактивний режим для заповнення форми відгуку в Chrome. Читає екран, завантажує контекст вакансії, генерує персоналізовані відповіді.

## Вимоги

- **Краще з Playwright**: Кандидат бачить браузер, Claude взаємодіє зі сторінкою.
- **Без Playwright**: Кандидат ділиться скріншотом або вставляє питання вручну.

## Workflow

```
1. ВИЗНАЧИТИ    → Прочитати активну вкладку Chrome (скріншот/URL/заголовок)
2. РОЗПІЗНАТИ   → Витягти компанію + роль зі сторінки
3. ЗНАЙТИ       → Збіг з існуючими звітами в reports/
4. ЗАВАНТАЖИТИ  → Прочитати повний звіт + секцію H (якщо є)
4.5 КАНАЛ       → Перевірити referral-source lock (чи вже задіяний рекрутер для цього роботодавця)
5. ПОРІВНЯТИ    → Роль на екрані збігається з оціненою? Якщо змінилася → попередити
5.5 KNOCK-OUT   → Сканувати форму на дискваліфікаційні питання (кваліфікація, PQE, патентний повірений)
6. АНАЛІЗ       → Визначити ВСІ видимі питання форми
7. ГЕНЕРАЦІЯ    → Для кожного питання — персоналізована відповідь
8. ПОКАЗАТИ     → Відформатовані відповіді для copy-paste
9. СТОП         → НІКОЛИ не натискати Submit/Send/Apply. Чекати явного підтвердження від користувача.
```

> **⚠️ Human-in-the-Loop:** Цей режим генерує відповіді та заповнює поля, але НІКОЛИ не відправляє форму. Фінальне рішення про подачу заявки — завжди за користувачем.

## Крок 1 — Визначити вакансію

**З Playwright:** Snapshot активної сторінки. Прочитати заголовок, URL, видимий вміст.

**Без Playwright:** Попросити кандидата:

- Поділитися скріншотом форми
- Або вставити питання як текст
- Або назвати компанію + роль

## Крок 2 — Знайти контекст

1. Витягти назву компанії та посаду
2. Шукати в `reports/` за назвою компанії (Grep, case-insensitive)
3. Якщо є збіг → завантажити повний звіт
4. Якщо є секція H (чернетки відповідей на форму) → завантажити чернетки як базу
5. Якщо НЕМАЄ збігу → попередити та запропонувати запустити auto-pipeline

## Крок 2.5 — Перевірка каналу (referral-source lock)

Перед підготовкою будь-якої ПРЯМОЇ заявки перевірити, чи роботодавець — юридична фірма і чи вже задіяний юридичний рекрутер: `config/profile.yml` → `legal.recruiter_channel.engagements`, плюс будь-який рядок у трекері для цього роботодавця з полем `via=`.

Якщо рекрутер (можливо) вже задіяний — **СТОП і попередити замість підготовки заявки**: перший рекрутер, що подав кандидата, зазвичай "закріплює" кандидатуру за собою на ~6-12 місяців, а пряма заявка поверх подання рекрутера створює спір щодо комісії, який фірми зазвичай вирішують, відхиляючи кандидата. Направити заявку через задіяного рекрутера або отримати явне рішення користувача продовжити напряму з усвідомленням ризику.

Inhouse- та держсекторні роботодавці за замовчуванням — пряма заявка; цей гейт спрацьовує лише коли існує рекрутерський канал.

## Крок 3 — Виявити зміни

Якщо роль на екрані відрізняється від оціненої:

- **Попередити кандидата**: "Роль змінилася з [X] на [Y]. Переоцінити чи адаптувати відповіді?"
- Оновити трекер за потреби

## Крок 3.5 — Сканування на "knock-out" питання

Перед генерацією повних відповідей прочитати всю форму на предмет "knock-out" питань — таких, що автоматично відсіюють кандидатів, які не відповідають критичним критеріям:

- **Кваліфікація/статус адвоката** (напр., "Чи маєте свідоцтво про право на заняття адвокатською діяльністю?") — звірити з `config/profile.yml` → `legal.bar_admissions`
- **Банд досвіду / PQE** (напр., "Скільки років практики за фахом?") — звірити з `legal.class_year`
- **Освіта/кваліфікація** (напр., "Вища юридична освіта?"; для IP-ролей: "Чи зареєстровані як патентний повірений?" — звірити `legal.patent_bar`)
- **Дозвіл на роботу / релокація** (для міжнародних/remote вакансій)
- **Зарплатні очікування/пороги**

Якщо knock-out питання виявлено і профіль кандидата може не відповідати вимозі — показати попередження та зупинитися до підтвердження користувача:

`⚠️ KNOCK-OUT: форма запитує "[текст питання]". Виходячи з вашого профілю, відповідь "[відповідь з профілю]" може призвести до автоматичного відхилення. Як відповісти, чи скасувати подачу?`

## Крок 4 — Аналізувати питання форми

Визначити ВСІ видимі питання:

- Поля вільного тексту (супровідний лист, "чому ця роль" тощо)
- Випадаючі списки (звідки дізналися, дозвіл на роботу тощо)
- Так/Ні (переїзд, віза тощо)
- Поля зарплати (діапазон, очікування)
- Поля завантаження (резюме, супровідний PDF, writing sample / зразок процесуального документа, deal sheet / перелік справ)

**Пакет заявки залежить від треку:** латеральний перехід у фірму = резюме + deal sheet/перелік справ (+ writing sample для судової практики); inhouse = резюме (+ опційний супровідний лист); держсектор/конкурс = супровідний лист + резюме + додаток про освіту + writing sample(и). Звірити слоти завантаження форми з потрібними документами та позначити, чого бракує кандидату, перед генерацією відповідей.

## Крок 5 — Генерувати відповіді

Для кожного питання:

1. **Контекст звіту**: Proof points з блоку B, історії STAR з блоку F
2. **Секція H**: Якщо є чернетка — використовувати як базу та покращити
3. **Тон "Я обираю вас"**: Кандидат має варіанти і обирає цю компанію з конкретних причин
4. **Конкретика**: Посилання на щось конкретне з видимого JD
5. **Мова відповідей**: Мовою JD. Для україномовних вакансій — українською. Для англомовних — англійською.

**Формат виводу:**

```
## Відповіді для [Компанія] — [Роль]

На основі: Звіт #NNN | Бал: X.X/5 | Архетип: [тип]

---

### 1. [Точне питання з форми]
> [Відповідь, готова для copy-paste]

### 2. [Наступне питання]
> [Відповідь]

...

---

Примітки:
- [Спостереження про роль, зміни тощо]
- [Пропозиції щодо персоналізації для перевірки кандидатом]
```

### Специфічні поля юридичних форм в Україні

- **Кваліфікація/статус адвоката**: номер свідоцтва, дата видачі, статус (діючий/зупинений), членство в НААУ — заповнювати лише з `config/profile.yml` → `legal.bar_admissions`, ніколи не вигадувати
- **Банд досвіду / PQE**: роки практики за фахом, звірені з `legal.class_year`
- **Патентний повірений**: номер реєстрації в Держреєстрі патентних повірених України (якщо релевантно для IP-ролі) — з `legal.patent_bar`
- **Практика-специфічні напрямки**: перелік практик з `legal.practice_areas`, що відповідають вакансії
- **Конфлікт інтересів**: якщо форма запитує про поточних/попередніх клієнтів — відповідати правдиво в межах конфіденційності, позначати як `needs_candidate_confirmation`, якщо дані не в профілі
- **Зарплатні очікування**: Вказувати в USD (для фірм senior-рівня, inhouse у міжнародних/tech-компаніях) або UAH (держсектор, місцеві компанії), уточнити gross/net та форму оформлення (ФОП/штат)
- **Дата початку**: Враховувати відпрацювання (2 тижні за КЗпП, для ФОП — за контрактом) та можливу затримку через перевірку конфлікту інтересів
- **Дозвіл на роботу**: Для українців в ЄС — тимчасовий захист (Temporary Protection Directive)
- **Мовні навички**: Українська (рідна), англійська (рівень — критично для міжнародних фірм/клієнтів), інші мови
- **Готовність до переїзду / timezone**: Уточнити поточну локацію та timezone overlap

## Крок 6 — Після відгуку (тільки після явного підтвердження користувача)

**СТОП.** Не продовжувати, поки користувач явно не підтвердить, що він переглянув відповіді та відправив форму самостійно.

Якщо кандидат підтвердив відправку:

1. Оновити статус на "Applied" через канонічний CLI: `node set-status.mjs <report#> Applied` (не редагувати таблицю `data/applications.md` вручну)
2. Оновити секцію H звіту фінальними відповідями
3. Запропонувати: `/career-ops contacto` для LinkedIn outreach
